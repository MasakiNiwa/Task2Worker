# Task2Worker

生き抜くためのタスク管理ダッシュボード

公開ページ: https://masakiniwa.github.io/Task2Worker/

## 特長

- 年次・四半期・月次・週次・日次・1日複数回の繰り返しタスク
- 実施してもリストから消えない(実施記録として残り、次の期間で再び未実施に戻る)
- 前回やり残したタスク・番号の記録漏れを表示
- 伝票番号などユーザー定義の番号をタスクと紐付けて管理・再利用
- 作業チェック表：対象日を含む期間の作業内容・実施状況・今回の番号・過去の番号を横並びで確認
- 番号の履歴表：日付・タスク・種類・番号・メモを一覧で検索、編集、コピー、再利用、削除
- 分析(年度→四半期→月→日のドリルダウン、達成率、曜日×時間帯ヒートマップ)
  - 集計は Web Worker、ヒートマップは WebGPU(非対応環境は CPU)で計算
  - 分析ツールは `src/features/analytics/tools/index.ts` に登録して追加できる
- スマホ / PC 両対応、落ち着いたダークモード、PWA(ホーム画面に追加・オフライン動作)
- データはブラウザ内(IndexedDB)に保存。JSON でバックアップ/復元、CSV 書き出し

## 番号を表で管理する

1. 「番号」の「種類」で、伝票番号・請求書番号などを作成します。
2. 「タスク」で作業を追加・編集し、「実施時に記録する番号」を選択します。
3. 「番号」→「作業チェック表」で対象日を選びます。月次ならその月、年次・四半期なら設定した年度に従う期間を表示します。
4. 表で実施をチェックし、「番号を記録」から登録します。番号が未記録の作業だけに絞り込むこともできます。完了後も行は消えません。
5. 過去の番号はコピーするか、「今回に再利用」で対象期間の新しい記録に引き継ぎます。以前の記録は残ります。

「番号の履歴表」は関連タスクがない番号やアーカイブ済みタスクの記録も表示します。スマホでは表を横スクロールできます。
実施チェックは選んだ期間に記録され、実施時刻には実際に押した時刻が残ります。
単独登録でも関連タスクを選べば日付から期間が設定されます。既存の期間なし記録も日付から判定するため、データの削除・再登録は不要です。

## 開発

```bash
npm ci
npm run dev        # 開発サーバー
npm test           # テスト
npm run lint       # Lint
npm run build      # 本番ビルド (dist/)
```

`main` にマージすると GitHub Actions でビルドされ GitHub Pages に公開されます。

### ディレクトリ構成

```
src/
  app/          テーマ・ルート定義(画面はここに登録するとナビにも反映)
  components/   共通 UI・レイアウト
  db/           IndexedDB スキーマ (Dexie)。変更時は version を上げて移行処理を書く
  features/     機能ごとのロジック
  pages/        画面
scripts/        ビルド補助スクリプト
```
